# フェーズ1: シンプルダメージ計算機 設計

## 概要

種族値・努力値・技の威力を入力し、ポケモンのダメージ計算式の骨格に基づいて
ダメージの範囲(最小値~最大値)を算出するシンプルな計算機を作る。

## 背景・全体像

本プロジェクトは将来的に以下のような拡張を予定している。

- PokeAPI のデータを SQLite/PostgreSQL に取り込んでホスティング
- ポケモンを6匹登録できるパーティ機能(持ち物設定を含む)
- 技データを PokeAPI から取得
- ポケモンの画像表示

これらは独立したサブシステムとして扱い、それぞれ別途設計する。本ドキュメントは
最初のサブプロジェクトである「フェーズ1: シンプルダメージ計算機」のみを対象とする。

ルールは「ポケモンチャンピオンズ」を前提とする。

## スコープ

### フェーズ1で対応すること

- レベル・個体値・性格を固定した上で、種族値と努力値から攻撃/防御(または
  とくこう/とくぼう)のステータスを計算する
- 技のカテゴリ(物理/特殊)に応じて、使用するステータスの組み合わせを
  切り替える
- 技の威力を入力し、ダメージ計算式の骨格に基づいてダメージの範囲を算出する
- 計算結果を画面に表示する

### フェーズ1で対応しないこと(将来のフェーズで検討)

- タイプ相性、STAB(タイプ一致ボーナス)
- 急所(クリティカルヒット)
- 天候・特性・持ち物による補正
- 性格による能力値補正
- PokeAPI 連携、DB、複数体のパーティ管理、ポケモンの画像表示
- ポケモン・技のマスタデータからの選択式入力(フェーズ1は数値の手入力のみ)

## 前提条件

- レベル: 50 固定
- 個体値: 31 固定(全ステータス「V」)
- 性格補正: なし(フェーズ1では適用しない)
- 努力値: 0~32 の範囲で入力可能。本家シリーズの「努力値÷4」の項に相当する
  値として扱い、個体値と同じ枠でそのまま加算する

## 計算ロジック仕様

### ステータス計算式

```
ステータス = floor( floor( (2 × 種族値 + 31 + 努力値) × 50 ÷ 100 ) + 5 )
```

- 攻撃側は、技のカテゴリが物理なら「攻撃」、特殊なら「とくこう」の種族値・
  努力値を入力する
- 防御側は、技のカテゴリが物理なら「防御」、特殊なら「とくぼう」の種族値・
  努力値を入力する

### ダメージ計算式

```
基本ダメージ = ( (2 × 50 ÷ 5 + 2) × 威力 × 攻撃ステータス ÷ 防御ステータス ) ÷ 50 + 2
```

レベルが50固定のため `(2 × 50 ÷ 5 + 2)` は定数 `22` として扱ってよい。

上記の基本ダメージに対して、乱数補正 0.85~1.00 を掛けた範囲を算出し、
最小値・最大値としてそれぞれ切り捨て(floor)で丸める。

```
最小ダメージ = floor(基本ダメージ × 0.85)
最大ダメージ = floor(基本ダメージ × 1.00)
```

## 入力項目

| 項目 | 対象 | 範囲・形式 |
|---|---|---|
| 技のカテゴリ | 技 | 物理 / 特殊 の選択式 |
| 技の威力 | 技 | 数値(正の整数) |
| 種族値(攻撃側) | 攻撃側 | 数値 |
| 努力値(攻撃側) | 攻撃側 | 数値、0~32 |
| 種族値(防御側) | 防御側 | 数値 |
| 努力値(防御側) | 防御側 | 数値、0~32 |

## 出力

- ダメージの最小値~最大値のレンジを表示する

## コード構成方針

- 計算ロジック(ステータス計算・ダメージ計算)は UI から独立した純粋関数
  として `lib/damage.ts` に切り出し、単体テストしやすくする
- 画面(フォーム・結果表示)は `app/page.tsx` に実装する
- 将来コンポーネント分割しやすいよう、フォーム部分は入力項目のまとまり
  (攻撃側/防御側/技)ごとに意識して実装する

## テスト方針

- `lib/damage.ts` の計算関数に対して、既知の入力・出力の組み合わせで
  単体テストを書く
- 画面のテストはフェーズ1では必須としない(手動確認でよい)
